# OnePlus 9 普通用户复现指南

普通用户的流程是：**下载我们已验收的发布版 → 连接自己的手机并采集必要设备文件 → 下载指定苹果系统 → 本地自动组包 → 启动 / 返回 Android**。
编译内核、驱动、UEFI 和加载器，以及 GPU、DMA、显示、触控、联网的发布验收，均由维护者完成。用户不用安装或运行验收程序。

## 当前能走到哪一步

截至 2026-10-25，公开下载已提供 CI 通用组件包，**尚未交付支持新用户从零完成上述流程的已验收发布版和本地准备工具**。
下面区分正式用户流程与现有工具状态，不把尚未实现的按钮或命令写成可用入口。

| 产物 | 现有状态 | 面向谁 |
| --- | --- | --- |
| `ci-lemonade-<commit>` | 自动测试、编译和公开下载已跑通；清单为 `hardware_verified: false`，缺少完整启动与本地准备工具 | 开发者集成 |
| `2026.10.25-base.4` | 已在维护者本机完成整包验收，绑定该手机；没有包含后续双缓冲改动 | 原绑定设备，不能拿来给另一台手机直接启动 |
| 面向新用户的已验收发布版 | 还需交付预编译启动组件、本机文件采集与系统组装工具，并接通发布版本检查 | 普通用户；目前不能仅下载 CI 包完成复现 |

普通用户入口应只提供维护者完成实机验收的配套版本。CI 构建成功、GitHub 的 Pre-release 标记以及某个旧 base 的验收记录，都不代表另一个版本已经具备这一条件。

## 1. 准备受支持的手机和电脑

- 当前设备证据覆盖 OnePlus 9 **LE2110 / SM8350 / 8 GB / AMB655X 面板**。其他地区型号、12 GB 版本和其他面板尚未验证，不能只凭 `lemonade` 名称判断兼容。
- 手机应已解锁 Bootloader，在 Android 中开启 USB 调试，并允许读取本机必要文件的 root 权限。本教程不执行解锁或 root；首次解锁会清除用户数据，应事先完成个人数据备份。
- 当前本机启动流程使用 Mac、Python 3.11+、`adb`、`fastboot` 和 USB 数据线。Windows / Linux 桌面的一整套用户流程尚未验证。
- 保持 Android 能正常启动。运行过程中保留 USB 连接，供系统上传、正常退出和返回 Android 使用。

## 2. 下载配套的已验收发布版

入口是 [GitHub Releases](https://github.com/b1ackm4x/hackios-xnu-kernel/releases)。选择明确列出支持硬件、指定 Apple 系统版本和维护者实机验收结果的用户发布版，按该版本清单下载并校验全部附件。

**目前公开的是 `OnePlus 9 CI ...` 组件实验版，普通用户流程在这里尚未接通。** 研究这些组件的下载与校验方式见 [CI 说明](LEMONADE-CI.md)；那不是另一套要求普通用户自行编译、验收的安装教程。

用户发布版应由我们提供已经编译好的内核、图形与网络运行库、UEFI / BootShim、加载器，以及本地准备和启动工具。用户不需要安装 Docker、THEOS、Xcode 或 Metal 编译工具链。

## 3. 连接自己的手机，采集必要设备文件

在用户发布版的本地准备工具中选择实际 USB 连接的手机，确认型号并在手机上允许 USB 调试和 root 读取。工具应只读取所需文件，保存到本机私有目录，并逐项核对手机端与电脑端的哈希。

| 本地输入 | 用途 | 处理方式 |
| --- | --- | --- |
| 设备身份、型号、内存、当前面板和固件版本 | 判断发布版是否支持这台手机，避免选错 USB 设备 | 本地核对；设备身份不随公共包发布 |
| 本机 DTB | 按实际硬件生成启动配置 | 保留原始副本；生成启动 DTB 时移除运行时身份信息 |
| 本机 Adreno 660 固件 | GPU 运行 | 当前构建使用六个 `a660_*` 文件，采集后校验 |
| 本机 QCA6490 固件与板级配置 | Wi-Fi 芯片运行 | 当前构建使用 `amss.bin`、`m3.bin`、`board.bin`、`regdb.bin`；板级文件按本机来源核对 |
| 启动链分区备份 | 保存原 Android 启动基线和恢复资料 | 仅在本地保存，不打入运行包，也不等同于完整用户数据备份 |

Wi-Fi 固件和板级配置不等于家庭 Wi-Fi 的密码或连接历史。准备工具不应读取或迁移已保存的网络、账号、密钥和应用数据；新运行环境不预置家庭网络。
这些必要输入只在本地使用，无需上传给维护者。

**现有实现：** `devices/oneplus-9/tools/lemonade-collect.py` 已能采集基线、DTB，并选择备份启动链分区；面板识别也已有工具。但 GPU / Wi-Fi 文件提取、清单生成和上述步骤还没有整合成普通用户准备入口。维护者需要补齐这一入口，不能让用户手工构造“已验证”字段。

## 4. 下载指定的苹果系统

当前代码使用 **iOS 16.5，构建号 20F66，iPhone X（iPhone10,3 / iPhone10,6）** 的系统文件。不能任意换成其他机型或较新 iOS。

来源由仓库中的 `sysimage/fetch-from-ipsw.py` 固定为 Apple CDN 的
`iPhone10,3,iPhone10,6_16.5_20F66_Restore.ipsw`。本地准备工具应按发布版指定版本下载、提取并核对所需系统文件；这一步不需要 Apple 账号或个人备份。

**现有实现：** `sysimage/fetch.sh` 可以在配置好的开发环境中下载和提取文件，但依赖 7-Zip、`cc` 和 `xnu-deps` 中的解压工具 / 源码。它还不是普通用户下载 CI 包后就能独立执行的安装器；需要将这些主机依赖随用户工具提供或自动准备。

## 5. 自动组装本机运行包

本地准备工具应将同一已验收版本的预编译组件、刚采集的本机文件和指定 Apple 系统组装到新目录，保留旧目录以便回退。组装包含生成启动镜像和 APFS 文件系统，不应要求用户重新编译项目。

工具负责检查：发布组件与版本清单一致；本机型号、内存、面板和固件属于支持范围；所有输入完整且与选中的设备匹配。**这些是兼容性与文件校验，不是让用户重跑发布验收。**

**现有实现：** `devices/oneplus-9/tools/lemonade-build-base.py` 能在维护者已准备好的工作区生成运行包，但依赖本地镜像、固件清单、已构建的启动组件等输入。`devices/oneplus-9/tools/lemonade-pack.py` 目前还会重新编译设备专属 loader；现有启动器也仍要求本机候选的 DMA / 联合验收记录。这些都是待改造的开发流程，不能直接作为普通用户入口，也不能通过复制旧记录或改布尔值绕过。

面向用户的工具需要认可**由维护者完成验收的确切发布组件和支持范围**，并对本地组装结果作完整性与设备匹配检查。设备文件不同导致最终镜像哈希不同，不应因此要求每位用户重新做 GPU、DMA 或网络测试。

## 6. 启动与返回 Android

完成本机准备后，运行包应提供以下入口；它们已经存在于维护者的本机 base 包中，尚未通过上面的新用户流程交付：

1. USB 连接为此包准备的手机，双击 `Start.command`。
2. 工具核对本机身份和文件后，使用 `fastboot boot` 临时启动，再上传系统到 RAM。本机现有包的系统上传约两分钟，其他连接的实际时间可能不同。
3. 在 iOS 桌面使用系统。需要联网时，由用户输入自己的 Wi-Fi 信息；原生设置首次输入密码的完整流程仍待维护者单独完成验收，不要求用户用联网测试脚本替代。
4. 双击 `Return-to-Android.command`，正常退出并返回原 Android，等待 Android 启动完成。

这些入口不刷写 Android 分区、不切换启动槽。当前系统只在 RAM 中运行，重启后设置与会话不保留；其他外设、长期稳定性和电源管理的范围见 [项目首页](../README.md)。

若出现设备不匹配、文件校验失败，或“候选尚未通过验收”，应保留错误并使用完整配套的用户发布版；维护者负责修复交付缺口，普通用户不需要运行 `lemonade-validate-base.py`。

## 给维护者：完成用户交付前还缺什么

1. 将 UEFI / BootShim、可供本机组装的加载器和主机准备工具纳入发布产物；CI 通用 EFI 目前不能直接代替设备绑定的 loader。
2. 接通一次本地准备：设备选择、必要文件采集、备份、哈希核对、Apple 系统下载与提取、APFS / 启动镜像组装。普通用户不配置编译环境。
3. 将维护者的实机验收结果绑定到确切发布组件和支持的硬件 / 固件范围；用户启动器验证这份发布依据及本机输入，不要求用户生成 DMA 或联合验收报告。现有候选检查在此机制接通前仍保留，不能只修改文档或标志来宣称工具已完成。
4. 在干净电脑和新的受支持设备上走通上述全过程，包括原生设置首次联网与返回 Android，再将该版本放入普通用户下载入口。测试副本、测试程序和家庭网络配置不进入用户运行包。

维护者的构建、集成和验收入口见 [CI 说明](LEMONADE-CI.md)、[移植工作记录](LEMONADE.md) 与 [base 开发流程](LEMONADE-BASE.md)。这些工作不属于普通用户复现的前置任务。
